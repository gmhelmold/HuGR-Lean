# HuGR-Lean Protocol V1 Semantic Contract

**Normative parent:** `docs/TECHNICAL_SPEC.md` §6  
**Runtime:** local in-process TypeScript

Protocol V1 names the facts exchanged between a host adapter and the HuGR-Lean core.

It is a **semantic contract**, not a required wire protocol.

Normal use is:

~~~ts
const result = engine.process(observation)
~~~

No subprocess, stdin/stdout transport, binary exit code, or JSON serialization is required.

## ObservationV1

~~~ts
interface ObservationV1 {
  schema_version: 1
  source: "shell" | "read" | "search" | "lsp" | "mcp" | "browser" | "other"
  command: string | null
  shell_dialect: "unknown" | "posix" | "power_shell" | "cmd"
  output: string
  termination: TerminationV1
  completeness: "unknown" | "complete" | "truncated"
  presentation: "unknown" | "terminal_rendered"
}
~~~

### termination

~~~ts
type TerminationV1 =
  | { kind: "unknown"; code: null }
  | { kind: "exited"; code: number }
  | { kind: "aborted"; code: null }
  | { kind: "timed_out"; code: null }
~~~

Rules:

- `exited` requires an integer exit code;
- non-exited states must not carry a code;
- `unknown` is never interpreted as success.

A shell source alone does not establish terminal-rendered presentation.

## FilterResultV1

~~~ts
interface FilterResultV1 {
  schema_version: 1
  decision: "passthrough" | "normalized" | "reduced" | "failed_open"
  replacement: string | null
  profile: string | null
  metrics: {
    input_bytes: number
    output_bytes: number
    saved_bytes: number
  }
  raw_ref: string | null
  diagnostics: DiagnosticCodeV1[]
}
~~~

### Decision / replacement contract

| decision | replacement |
|---|---|
| `passthrough` | MUST be null |
| `failed_open` | MUST be null |
| `normalized` | MUST contain replacement text |
| `reduced` | MUST contain replacement text |

The adapter already owns the original tool output, so passthrough/failed-open results do not echo it.

### Metrics

Metrics are exact UTF-8 bytes at the HuGR-Lean boundary.

For passthrough/failed-open:

~~~text
output_bytes == input_bytes
saved_bytes == 0
~~~

For normalized/reduced:

~~~text
output_bytes == UTF-8 byte length of replacement
output_bytes <= input_bytes
saved_bytes == input_bytes - output_bytes
~~~

## Diagnostics

Protocol V1 recognizes bounded diagnostic codes including:

~~~text
ambiguous_profile
profile_parse_failed
preservation_failed
input_too_large
raw_store_failed
protocol_warning
incomplete_input
unknown_termination
termination_not_exited
safe_normalization_failed
~~~

Diagnostics are side-band and are not appended to model-visible text.

## Fail-open boundary

The host adapter retains the original output before calling HuGR-Lean.

If:

- observation validation throws;
- core execution throws unexpectedly;
- the returned result fails result validation;
- the adapter cannot safely apply a replacement;

then the original host output remains authoritative.

## Optional serialization

A future adapter, test tool, or debugging utility MAY serialize Protocol V1 as JSON.

Serialized representations MUST preserve the same field names and semantic invariants, but serialization is not part of the normal v1 runtime path.
